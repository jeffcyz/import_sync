Task: Build a Lossless Markdown-to-Flat-JSON Converter

Implement and execute the conversion, not just propose a solution.

Validation Warnings Master List - Snip_from_xlsb.md

* validation_master_parse_report.json — structural validation and any parsing anomalies.
* markdown_to_flat_json.py — a reusable converter supporting an input file path and optional output path.

Use Python’s standard library wherever possible.

Read the original Markdown directly. Do not use screenshots, OCR, LLM-based transcription, or an existing reconstructed JSON as the source of truth.

Preserve these column names and their original order exactly.

Each JSON object must contain three additional metadata properties before the source columns:

* record_id

* row_type

Therefore, each JSON object must have exactly 25 keys.

3. Flat JSON structure

The output must be a top-level JSON array containing one object per original data row.

For a numbered record:

* record_id: integer extracted from column # (e.g. "1.0" becomes integer 1).
* parent_record_id: null.
* row_type: "numbered".
* Keep the original # cell as a string, e.g. "1.0".

For an unnumbered continuation row:

* record_id: null.
* parent_record_id: the preceding numbered record ID.
* row_type: "unnumbered_continuation".
* Preserve the entire original 22-column row, including cells containing NaN.

These continuation rows must remain independent JSON objects, even when they contain only an additional WARNING, or when they contain their own SCRIPT NAME.

Do not merge continuation rows into numbered records.

4. Parsing requirements

Implement deterministic table parsing.

* Identify and skip the Markdown table header and separator row.
* Parse each data row into exactly 22 source fields.
* Use Markdown-aware pipe splitting. Support escaped pipe characters (\|) inside cell content.
* Do not split URLs, formulas, or descriptions incorrectly.
* Distinguish display/terminal line wrapping from actual Markdown row boundaries.
* Preserve row order exactly as it appears in the source.
* Preserve trailing empty columns.
* Strip only Markdown delimiter padding; do not normalize internal text.
* Preserve the original capitalization, punctuation, misspellings, spacing within text, formulas, names, dates, and complete URLs.
* Preserve literal NaN and NaT as strings.
* Do not automatically replace missing values with null, zero, or empty strings.
* Do not automatically convert dates or thresholds into typed Python values.
* Do not perform business-rule interpretation or text summarization.

If a row cannot be parsed unambiguously into 22 columns, report the source line number, raw content, and parsing problem. Never silently discard, truncate, pad, merge, or guess data.

Generate validation_master_parse_report.json with:
